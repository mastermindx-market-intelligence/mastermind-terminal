## Native WTI route

The shared directory opens `/wti-live-path`. The route uses the verified billing session and the Macro-owned site-full read. The only upstream request is GET `/api/ontology/explorer/v1?chain=oil_inflation_duration_derate`. The response is bounded, private and never cached by the reader. Terminal projects typed fields and renders the episode state, supplied first blocker, four conditions, individual tests, source clocks and comparison. Boolean false, unknown, zero, strict thresholds and different units have separate render meanings.

The selected condition is represented by the existing `#ox-leg-…` fragment. A mismatched `rev` is disclosed. A Company return for a supported WTI condition restores that selection. Other chains, advanced scenarios, portfolio and company investigations retain the full explorer. Keep the inbound legacy alias until those workflows and production access have passed the cutover checks. Never place archived member readings into a guest response.

## Verification

Studio Chrome exercised the native guest route, directory entry and mobile sign-in sheet. Widths checked were 1440, 768, 390 and 320 pixels, including Chinese at 320. The actual Macro working-checkout composer also fed the production Terminal parser independently. Unit tests cover session denial and entitlement refusal, the selected condition and revision, first-blocker consistency, source disagreement, the return URL and bounded response handling.

Release proof still requires a deployed authorized account opening the real gateway data, selecting a condition, returning from a company, and signing out cleanly. Check the sibling pages against their respective producers before classifying them as native. The WTI design, linked scenario entry and a complete native scenario editor represent different stages of delivery.
