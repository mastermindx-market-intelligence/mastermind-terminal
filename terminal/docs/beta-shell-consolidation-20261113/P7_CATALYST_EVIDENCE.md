# P7A — Native Catalyst evidence desk

## Outcome and limits

Catalyst Intelligence now presents a compact, source-ordered watch list beside
one selected evidence case. The case makes its three unanswered research
questions visible: a verified event, company exposure/economics and entry
conditions. A clear return action restores the originating list control without
discarding the selection or filters. Continuations follow the case's admitted
source links; an Energy case no longer offers Defense as if the source connected
the two.

This is presentation and navigation over the existing native Catalyst and
Defense owners. It does not create a new signal, ranking, theme model, company
universe, event verification, trade recommendation or saved-watch service.
BioCatalyst and the full Government/Defense workspace remain distinct specialty
products with useful depth. Their engines and original entrances are retained.
The parent P7 and P0–P17 acceptance remain open.

## Selection, focus and access lifetime

The existing `case` URL, popstate handling, local filter state, show-more limit
and copy lifetime remain the owners. An explicitly selected case stays selected
when filters exclude it; the page explains that state. A saved case absent from
the accepted source stays absent rather than silently selecting another case.

The return control remembers only a deliberate Inspect action and binds it to
the exact accepted view, read context and theme. It focuses that still-mounted,
visible control; otherwise it focuses the persistent watch-list heading. It
does not change the URL, filters, selected case, list limit or read generation.
Browser Back/Forward clears this transient return intent. Existing account and
refresh invalidation prevent old read details, links or copy feedback surviving
an access change. No new data request or storage write is introduced.

The independent Defense panel remains outside the market success/error branch.
A market transport failure leaves independently readable Defense evidence
available. A shared-entitlement denial still withdraws both through the existing
workspace owner, and a new authorized read can recover. This slice neither
weakens the denial nor creates an alternate read path.
