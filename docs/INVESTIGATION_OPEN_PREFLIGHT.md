# Unified Investigation OPEN: source preparation

This candidate does **not implement OPEN**. The baseline read and Saved mutation
handlers keep their existing common guard. The normal installer remains CLOSED.
No configuration, SQL, service, admission record or user operation is changed.

`ops/investigation-open-preflight.sh --target beta --target-sha <40-hex>` is a
read-only **future native invocation**, not an instruction to run it while
runtime effects are held. It sources the existing `terminal-build.sh` library
through its incumbent sourced-file entrance and uses its fixed beta profile.
It requires source containment, the real ordinary accepted-runtime validator
(including provenance, pending-attempt refusal, rollback baseline and live
marker/build binding), an exact requested/installed SHA match, and the existing
CLOSED selected-unit/serving-process verifier. It creates no parallel accepted
record. Production and arbitrary profiles are unsupported.

A qualified installation returns `SOURCE_PREPARATION` and exit 78, with four
precise missing source contracts. It never returns ready or activates OPEN.
`ready=true`, supplied attestation JSON, health, flag state or an empty pending
count cannot replace these contracts.

## Remaining source contracts and held observations

1. **All-ingress/direct-RPC/drain observer.** It must consume the incumbent
   qualified fleet/ingress identity and actual database-role closure evidence,
   with an exhaustive current set and bounded observation identity. One unit's
   CLOSED setting cannot establish other API instances or direct RPC closure;
   closing admission does not cancel already-admitted requests. The retained
   S11 record contains an actual refused fleet-metadata effect, not an accepted
   observation contract that this candidate may silently replace.
2. **Original-operation reconciliation verifier.** It must consume original
   operation identities and definitive same-operation receipts/fences. The
   retained CREATE/15 UNKNOWN labels do not provide an authoritative complete
   machine-readable operation inventory. An empty caller-provided list, receipt
   miss, elapsed time or another operation cannot establish reconciliation.
3. **Lawfully admitted schema/grants receipt verifier.** It must bind the exact
   approved migration bytes, database/schema target, application/readback and
   actual grants to the installed API contracts. SQL0030's original T03k refusal
   and unaccepted return remain held. No new receipt issuer is invented here.
   Dependent migrations are required by their actual enabled scope; 0048 is not
   a blanket Investigation prerequisite.
4. **Unified OPEN adoption/recovery transaction.** Only after those real
   qualifications exist can a source-owned transaction change the selected
   configuration and prove process adoption, preserving source/runtime/rollback
   identities and original uncertain outcomes. It must extend the existing
   owner's custody rather than create a second lifecycle or accepted registry.
   A configuration or restart lost response must not trigger blind repetition.

These missing contracts are engineering inputs; no historical-owner ACK is
required. Their positive runtime truth cannot be manufactured from fixtures.
This preparation exposes the exact gaps without claiming the S17 outcome done.

all-ingress/direct-RPC closure and drain with original-effect reconciliation,
lawfully admitted exact SQL qualification/application/readback, then separately
admitted activation and authenticated acceptance:
[original ruling](https://github.com/mastermindx-market-intelligence/mastermind-terminal/pull/804#issuecomment-6547233146).

revoke-before-migration (0030 regrants), a temporal freeze as a stale-client
barrier, and old-binary rollback after new relation-bearing manifests. This
candidate does not retry those effects, apply SQL, split the common guard or
add a B1-only exception. Baseline GET itself has no Investigation SQL RPC;
the mutation predicates apply because the existing OPEN switch is unified.

Tests use the real incumbent library with explicit hermetic observation seams.
They prove refusal/composition behavior, not host, fleet, database, authenticated
rights, drain or OPEN activation. The existing Python CI discovery runs the new
test from the repository root; no workflow, scheduler or service is added.
