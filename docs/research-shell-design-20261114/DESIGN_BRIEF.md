## The experience to build

The user should recognize the page’s job immediately, get one useful answer, and inspect the reason without losing their place. The shell supplies identity, navigation and shared tools. The page supplies its specific instrument: reading, retrieval, comparison, a ledger, a hierarchy, a calendar study or a transmission path.

The distinction matters. A report reader should not resemble a ticker dashboard. A filing comparison needs aligned passages. Memory needs a visible information cutoff. A flow decomposition needs an arithmetic receipt. Consistency comes from typography, spacing, selection, source inspection and return behavior—not from making every page a card grid.

### Composition rules

- Lead with the primary result or task. Keep supporting summaries to two in the first viewport. Prefer removing a module to shrinking its text.
- Use the existing shell once. The study’s frame is a visual stand-in; implementation must consume AppShell rather than copy its rail, header, account controls or route ownership.
- Make selection neutral and actions clear. Status color belongs to the affected value, never to decorative container edges.
- Retain a limitation beside a result when it changes that result’s meaning. Move method detail, long source metadata and secondary tools into a named disclosure.
- Give dates a precise role: observation time, holding period, filing date, publication cutoff and build time are different.
- Preserve stable source/entity identities when display names change. Never substitute a new score for the existing engine’s output.
- Keep explanatory copy concrete. “What changed,” a source date or a comparison basis is useful; a banner describing the page’s existence is not.
- Support keyboard and touch. Charts must have readable alternatives. Inspection closes to the trigger; navigation restores the selected item, filters and reading position.
- Respect reduced motion. Animation may clarify a state change; it must not suggest a source is live or create visual urgency.

### Visual direction in the study

The proposed light canvas uses `#f5f6f8`, white working surfaces and `#1a202c` text. The dark canvas uses `#0a0b0e`, `#0f1218` working surfaces and `#e3e8f1` text. Neutral rules separate modules; blue identifies a deliberate action or selected chart series. Positive, negative and caution colors encode the named observation only.

The study uses a system/SF/Inter stack, a 28px page title, mostly 14–15px working text, readable table cells and restrained metadata. Its spacing and radii are a proposal to reconcile with Terminal’s existing tokens, not a parallel production theme. Generous gutters and selective disclosure carry the information hierarchy.

Desktop intent is 1440px. Complex reading/comparison views require a deliberate 820px composition. Mobile intent is 390px, with stacked inspection, horizontally contained tables, navigable event strips and a source-list alternative to the network. These are specified/CSS-authored breakpoints; they have not been visually verified.

## Core Research: studies 1–11

### 1. Intelligence Hub

**Question:** What changed enough to deserve my attention, and what evidence supports or challenges it?

**Composition:** A concise market reading and three developments form the primary surface. Selecting a development opens its context, a restrained comparison chart and Evidence/Against views. Changes and Record are separate lenses, preserving the difference between a new observation and retrospective tracking. A catalyst and one relevant authored report provide the next useful actions.

**Interaction:** Select a development → inspect supporting and contrary evidence → open the source record → close to the selected development. Save records the selected item in the local preview; production uses the incumbent saved-research owner. A missing desk removes the apparent full desk count rather than filling a missing vote.

**Preserve:** Four voting desks, contextual nonvoting policy input, original observation time and record identities. Do not add a synthesized confidence/rank score or treat a desk consensus as execution permission.

**Owner:** `scripts/build_intel_hub.py`; `engine.intel_hub`, Hub record/grader, signal governor and QLedger. Terminal’s existing `/intelligence` is a different macro/Prophet/sector surface; route reconciliation must not silently overwrite it.

**Paper states:** Default briefing; selected counterevidence; changes/record; one desk unavailable; mobile inspection and return.

### 2. Mastermind Portfolio

**Question:** Which research changes affect what I actually own, including exposure shared across holdings?

**Composition:** Actual portfolio value and its price basis lead into a holdings table or shared-exposure view. The selected holding explains the relevant change and its shared driver. A small event module answers what is coming next. Watchlists remain a separate collection.

**Interaction:** Select a holding or exposure group → inspect the driver and related holdings → open holding research → return to the same selection. Holdings editing/import belongs to the existing Portfolio flow. The study does not write holdings or claim a complete imported account.

**Preserve:** Currency, valuation clock, missing-price/sizing completeness and the distinction between an actual holding and an observed name. The partial specimen retains a complete prior-close snapshot when one current price is unavailable. Exposure remains descriptive.

**Owner:** Existing native `/portfolio` and `portfolio_positions`; Macro portfolio intelligence for concentration, correlation, factors, stress and events. Active Portfolio carriers and release holds remain in force.

**Paper states:** Holdings; selected shared driver; event context; incomplete valuation; empty/import review; mobile table and inspection.

### 3. Mastermind Bot

**Question:** What did the simulated account do, what was known at that moment, and how did the later observation differ?

**Composition:** A clearly identified paper account sits above its decision ledger. The selected record separates At decision from Later outcome. Original observed/considered/chosen steps belong to that exact record. Positions and account record are secondary lenses; costs, modelled fills and strategy version are available through account assumptions.

**Interaction:** Select a decision → read its original explanation → inspect the original record → switch explicitly to the later observation. A missing original explanation leaves the recorded action/time available and does not synthesize a rationale.

**Preserve:** Simulation identity, modelled execution costs, exact decision cutoff and original versus later annotations. The original service at `bot.mastermind-x.com` has not been API-audited here; charts and account integrations remain proposed until its contract is inspected. No live order controls are designed or executed.

**Paper states:** Decision ledger; selected reduction versus no-action record; missing rationale; costs/fills; outcome window still open; narrow layout.

### 4. Research Reports

**Question:** Which authored argument should I read, and what would change its conclusion?

**Composition:** An editorial lead and restrained report cards lead into a comfortable reading surface with section navigation. The reader gives the thesis, changes, countercase and observations to watch. Sources and edition history are tools beside reading, not an always-open administrative panel.

**Interaction:** Filter by subject → open the exact report → navigate sections → inspect its source → return to the same filtered list and position. The four study articles have distinct original text. Topic filters exclude other topics. Reader navigation creates/restores local history snapshots.

**Preserve:** Authored editorial identity, bilingual bodies, publication/edition history and stable source references. Reports and Vault retain different content jobs.

**Owner:** `scripts/build_reports.py` and its authored report registry/full bodies. Reuse the native reading primitives where compatible without collapsing these into institutional search records.

**Paper states:** Editorial index; selected article; mobile section controls; source unavailable with article retained; updated edition and return path.

### 5. Research Vault

**Question:** Where is the exact document or passage that answers my research question?

**Composition:** Search and source filters lead to document results and a selected reading surface. Text/Original toggles preserve document identity and passage position. Source details reveal version and selected passage; long metadata stays behind Record details.

**Interaction:** Search → filter → select document → move between that document’s passages → inspect source/version → return. Each specimen document has its own passage set. Changing a filter that changes the selected document resets the passage safely. A PDF failure retains authorized text and metadata instead of blanking the search results.

**Preserve:** Query, source scope, result identity, original hash/version, entitlement, passage/page identifiers, reading progress and valid original-document access. The study’s Original view is a labeled HTML specimen, not a real PDF.

**Owner:** Existing `terminal/components/workspaces/ResearchWorkspace.tsx`, shared-shell research catalog/search/read/PDF APIs and `readingProxy`; Macro `site/research_vault_app.js`. Extend these owners.

**Paper states:** Search/results; matched passage; original PDF; unavailable PDF with text retained; no results; access-restricted document metadata; mobile reading/return.

### 6. Earnings Wire

**Question:** What changed in this event, and what words in the original packet support the reading?

**Composition:** A bounded event list leads to one event headline and three material claims. Selecting a claim aligns the source passage. A comparison view shows prior/current language only when both packets exist. Weekly briefing and company context extend the reading journey.

**Interaction:** Select event → select claim → inspect its exact packet → compare calls → return. The three event specimens have distinct claims and source context. When a prior packet is unavailable, the current call remains readable and comparison is explicitly unavailable.

**Preserve:** Immutable source packet/event identity, pagination, source/version clock and the distinction between verified source and interpretation. Current-page filtering must not masquerade as a global earnings search.

**Owner:** `scripts/build_earnings_public_wire.py`, event packets and paginated index. Any global-search extension requires a real API/coverage contract.

**Paper states:** Event/claim; aligned source; prior/current comparison; missing prior call; weekly brief; mobile event strip.

### 7. Filing Forensics

**Question:** What changed in the filing, on what comparison basis, and what should I inspect next?

**Composition:** A short change index controls aligned previous/selected passages. The periods and revisions remain visible above the redline. Changes/Clean reading separates markup from reading. Questions and value receipts sit below the comparison.

**Interaction:** Select a disclosure → inspect the aligned change → choose the actual previous revision → apply it → open the original/value receipt. Reopening or cancelling the revision chooser preserves its active basis. The amended specimen changes both the source identity and the compared passage.

**Preserve:** Original/latest/restated versions, period alignment, statements, disclosures, timeline, peers, source receipts and existing deep routes. A wording change does not imply misconduct. Advanced tools belong in named views rather than being discarded.

**Owner:** `templates/fundamental_forensics.html.j2` and its existing JavaScript/data contracts.

**Paper states:** Redline; clean reading; amended previous filing; value receipt; unavailable comparison period; narrow sequential comparison.

### 8. Neural Web

**Question:** Which available source families support, challenge or fail to inform this instrument’s reading?

**Composition:** An inspectable source network and an equivalent source list share selection. Disagreement isolates contrary/mixed evidence. A selected family explains its meaning and source time. Node size is uniform. An edge means a source relationship; it does not encode weight or causation.

**Interaction:** Select source → inspect context → isolate disagreement → return to all sources. Missing evidence is named Unavailable, distinct from Unchanged or Disagrees. Mobile starts with the readable list; a deliberately selected graph may scroll within its own viewport.

**Capability boundary:** The current public Neural Web is an explanatory/marketing page with animated SVG. The study’s interactive evidence explorer is **proposed**, not an observed live graph engine. Source availability, rights and a permitted payload contract must be established before implementation. Proprietary weighting remains protected.

**Owner:** Existing Neural Web explanation and authorized source families; no new fused scoring owner is introduced.

**Paper states:** Network; list; disagreement; one missing family; selected source; accessible focus/touch and mobile list.

### 9. Market Memory

**Question:** What was known in a retained reading, how does a historical comparison differ, and what is available now?

**Composition:** Saved readings, Historical comparisons and Current context are distinct tasks. The historical chart retains an explicit information cutoff. Then known contains only observations available at that cutoff; Later observed is a separate retrospective view. Current context has its own source clocks and no future-reveal control.

**Interaction:** Select saved episode → inspect known-time evidence → optionally reveal later observations under the retrospective label → inspect comparison inclusion/basis → return. Selected evidence follows the actual episode. A later recovery label cannot appear in the saved point of view.

**Preserve:** Original retained output, cutoff, method/version and retained-versus-recomputed separation. Similarity describes context, not a forecast. Registered experiments and sealed holdouts remain untouched. The pre-2020 examples are invented design inputs; no historical experiment ran.

**Owner:** `templates/market_memory_retained.js` and the retained/source record contracts.

**Paper states:** Then-known chart; later-observed chart; retrospective candidate comparison; current source context; incomplete retained packet; mobile cutoff/selection.

### 10. Market Reference

**Question:** What does this measure mean here, how is it read, and where can I return to use it?

**Composition:** Search and a term list lead to one clear definition, a concept-specific example and comparison guidance. Formula/conventions is a disclosure. Contextual return keeps reference from becoming a dead-end encyclopedia.

**Interaction:** Search → select term → inspect the relevant example and calculation convention → return to the originating research. The study varies the illustration for breadth, real yields, liquidity, free cash flow and relative strength; it does not reuse an unrelated chart for all terms.

**Preserve:** The closed bilingual definition registry, explicit convention, population/window and where-used links. Production return context must come from the referring page rather than always returning to Hub; the current study has a bounded Hub-return specimen.

**Owner:** `config/market_reference.yml` and its existing page consumers.

**Paper states:** Search/definition; formula expanded; no matching term; source-method gap; contextual return; mobile term strip.

### 11. Morning Edition

**Question:** What should I understand before this session, what could change it, and when should I look again?

**Composition:** An editorial brief gives overnight context, what could change the reading and one useful report. A compact market strip retains each source’s basis. The session clock provides relevant events; holdings context is a focused follow-through.

**Interaction:** Read the brief in sequence → inspect the source/tape → open a relevant report or holding → return to the edition. Progress in the study advances to the chosen section locally. Previous editions retain their original cutoff. A late item is identified by arrival time after that cutoff.

**Preserve:** Deterministic prior-close briefing, existing ordering and source clock states: CURRENT, STALE, UNAVAILABLE, NOT_COVERED, NOT_YET_OPEN and CLOSED. No decorative live pulse or global “live” status.

**Owner:** `scripts/build_am_edition.py` and its existing source/edition artifacts.

**Paper states:** Pre-market edition; closed/not-yet-open session; late update beside retained edition; previous edition; mobile sequence and return.
