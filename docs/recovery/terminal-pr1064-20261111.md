### Consumer defects and repair

The native model uses an internal half-open slot window, but its public time-scale
handle incorrectly exposed that window directly. The installed LWC 5.2.0 adapter and
existing linked-pane consumer use inclusive endpoints. A time window over bars 0–9
therefore returned native `{0,10}` against LWC `{0,9}`; the consumer's valid earliest
window `{-8,1}` was shifted by native to `{-7,2}`.

The public native get/set/subscription boundary now converts the right endpoint once.
Internal input, clamps, painting and model projections keep their half-open convention.
Exact accepted fractional requests retain their bitwise endpoints, and subscription
wrappers preserve handler identity, duplicate-subscription and unsubscribe behavior.
The parity harness now sends the same public range to both real adapters.

The drawing bridge also reconstructed spacing from the old endpoint convention.
That was a real consumer defect: semantic anchor round trips drifted from logical 2
to 1.791666…, and a raw anchor disagreed with the real native time projection.
The bridge now probes two adjacent integer logical coordinates near the visible
window and interpolates from those actual pixels. This preserves renderer-specific
pixel origins and fractional raw/future anchors without using LWC's snapped inverse.
Missing or invalid projection still fails closed; pane price-readiness checks remain.
Real-adapter regression cases retain exact logical 6, 6.25 and 6.75 anchors on both
LWC and native, with the original pixel coordinate on the return path.

Focusing an exact bar at maximum zoom had a related endpoint-span error: an inclusive
two-slot view was rejected and expanded to 81 slots. `placeFocus` now uses the existing
`MIN_LOGICAL_SPAN` contract. The new case reproduces `{250,251}` becoming `{0,80}`
before the fix, then requires `{39.5,40.5}` and the exact crosshair at bar 40 afterward.

Fixture changes preserve physical slot counts and internal right-offset/clamp
assertions. No drawing semantic assertion, cross-engine document equality, browser
assertion, timing budget or acceptance requirement was weakened. A bounded production
consumer audit found save/restore, calendar synchronization, view reset, history refresh
and indicator culling compatible with the inclusive public boundary. Existing keyboard
percentage approximations were left outside this correctness repair.

### Concrete test-input defect

The existing browser setup repair #1469 enabled actual browser assertions after the
Ubuntu mirror failure. Its mobile-2 job recorded a retry-passing failure in the
symbol-wheel / ticker-picker journey:
https://github.com/mastermindx-market-intelligence/mastermind-terminal/actions/runs/43041983641/job/130597305329
The drawer had already opened at its initial detent and expanded to full. The failing
assertion followed the 70 px downward gesture: expected `initial`, received `full`.
It did not show stale full-detent state on initial presentation.

The test described that input as a quick flick but sent separate awaited Playwright
commands without defining its duration. The component computes release velocity from
the last pointer-move sample. That sample moves 21 px, so an inter-command interval
above 46.7 ms makes it slower than the existing 0.45 px/ms flick threshold. A 70 px
slow drag from full correctly stays full. This is a concrete matching failure
mechanism; the original CI log did not record event timestamps, so it does not prove
the measured timing of that individual retry.

Only the two explicitly described short-flick call sites now use a serializable test
helper that dispatches real PointerEvent instances through the component handlers
with positive, monotonic sample times over 80 ms. The last movement is 21 px over
24 ms, or 0.875 px/ms. The test retains its 70 px distance, detent expectations,
focus checks and final symbol-selection journey. Other drag call sites retain their
existing behavior. No product threshold, component lifecycle or assertion was changed.

The helper is exercised against the real MobileSheet component: a slow 70 px drag
from full stays full, while the same path over 80 ms returns to the initial detent.
The subsequent initial-detent gesture reaches the existing dismissal callback.
That final 70 px dismissal alone is not a velocity falsifier because it also exceeds
the component's 56 px distance slack; the full-detent slow/fast comparison is the
velocity-sensitive proof.
