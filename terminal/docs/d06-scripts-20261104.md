# D06 Scripts implementation — 2026-11-04

## Delivered behavior

The existing Pine editor now keeps save outcomes visible and tied to the exact script, source, inputs and optimistic-concurrency revision. A network failure, malformed receipt, conflict or server failure does not invite a duplicate write. The user explicitly checks the existing library read endpoint, compares the saved version, then keeps local edits or confirms replacement.

Successful receipts must identify the same script and advance its revision. Readback compares the complete saved name, source and semantic input values. A same-revision read does not establish that an uncertain write is finished. Later typing stays in the editor. Replacement confirmation is bound to the displayed revision and current buffer; a new read or edit renews it, while an unrelated diagnostic check does not erase it.

Save-and-switch and Add-to-chart carry a one-use navigation intent. Cancel, renewed navigation, selection changes and newer typing prevent a late save from navigating. Add joins no unrelated pending save and requires diagnostics for the current input generation. The real Terminal route consumes the saved script ID through its existing library and chart-engine owner.

Diagnostics describe their actual scope: 130 synthetic bars and a one-second run budget, not a backtest. Cancelled, pending, failed and completed checks remain distinct. Reverting A→B→A cannot reuse a result from a prior edit generation.

The library, picker and unsaved-change dialog are keyboard operable. The dialog traps focus, supports Escape and returns focus to a persistent opener. Controls stay disabled until the editor owns input events. Narrow layouts use one reachable page flow, local two-dimensional source scrolling, 44px actions, visible blocked reasons and EN/ZH copy. Protected built-in scripts retain read-only behavior.
