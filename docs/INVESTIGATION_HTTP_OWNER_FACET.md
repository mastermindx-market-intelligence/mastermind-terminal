## Request primitive

private unavailable response. `investigationBootAdmission.ts` adds a negative
floor: a bounded Linux own-process `/proc/self/environ` read must contain exactly
one literal startup `INVESTIGATION_API_ADMISSION=open`. A CLOSED module import
performs no environment-file IO. Missing, duplicate, malformed, oversized,
unsupported-platform/worker or failed reads deny; no `process.env` fallback can
upgrade them. The source uses ordinary Next Node runtime routes and Node fs;
controlled VM tests do not qualify a production Next build or Linux observation.

Linux documents this file as the initial execve environment; later ordinary
putenv changes are not reflected. Native code can alter that memory or the
prctl environment bounds. This is not tamperproof or an attestation:
[Linux proc_pid_environ](https://man7.org/linux/man-pages/man5/proc_pid_environ.5.html).
The bounded reader consumes until EOF, closes and wipes its buffer. It never
returns/logs raw environment bytes, unrelated values or their hashes.

a nonconfigurable/nonwritable negative Symbol also prevents a subsequent OPEN.
Separately compiled route copies in one global share that negative property;
separate VM globals do not. Worker threads refuse the boot reader. A born-CLOSED
kernel environment remains a floor in each copy, but no code here attests an
unobserved intermediate env change before lazy import. There is no positive
