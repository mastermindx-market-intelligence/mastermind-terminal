## Implementation decisions

- Use the chart engine's rendered time-scale width and axis widths, together with the actual pane and grid geometry. Configured engine width is not a rendered measurement.
- Reserve the engine's possible one-pixel even-size rounding loss once. Feeding that alternating loss back into layout caused a boundary oscillation; the current code measures the stable occupied width separately.
- Retain the existing OptionsRail, context portal host, chart engine, selection and persisted `mm.railW` owner. Responsive fitting never overwrites the requested preference.
- Account for the actual grid column count and gaps. Two chart columns move the same rail below; returning to one restores the saved preferred width when it fits.
- Let keyboard users resize with arrows (10 pixels, or 40 with Shift), Home/End and a visible reset action. Preserve cancellation and release all pointer listeners/cursor state.
- When the separator disappears, return owned focus to the reader. The reader's new focus/back action uses the existing focused-chart state.
- Keep the drawing toolbar within its chart height and scroll its controls. Existing floating menus and style palettes remain reachable.
- Contain the reader's visually hidden feedback status within its feedback group. It no longer creates blank document overflow when the help disclosure opens.
