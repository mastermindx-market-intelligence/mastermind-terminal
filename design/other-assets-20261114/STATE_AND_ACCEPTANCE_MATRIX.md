## Shared state contract

| State | Expected behavior | Must not happen |
|---|---|---|
| Initial loading | Keep the subject, navigation and stable analytical geometry; load only the affected region | Blank shell, layout jump or invented zero |
| Available | Show qualified value, source definition and local observation context | Page-wide timestamp falsely qualifying every source |
| Empty selection | Explain that nothing is selected; provide a recovery that actually restores a selection | “Reset” changing only an unrelated state flag |
| No applicable records | Explain that the selected window has no model changes/events | Invented records or a generic source-failure state |
| Partial | Preserve independent valid inputs; identify withheld aggregate/fields | Hiding a number while retaining its color, tooltip or click result |
| Stale | Show the last qualified date and the applicable reading limit | An apparently current number with a buried stale footnote |
| Unavailable | Withhold the value and explain the specific missing prerequisite | Zero, a made-up fallback, or an alternative provider that evades a denial |
| Not applicable | Explain why the calculation does not answer this question | Infinite coverage or a misleading denominator |
| Revised | Preserve original/revised values and affected vintage | Silent overwrite of historical inputs or decisions |
| Conflicting | Keep both observations visible and attributable | A new synthetic score that hides disagreement |
| Historical | Move all dependent panels to the same qualified vintage | Current allocation/drivers beside an old price chart |
| Hypothetical | Label the mode, base observation, parameters and approximation | A scenario presented as observed, forecast, account exposure or action |
| Local input draft | Preserve typed content by instrument and task; show persistence scope | Theme or inspector interaction erasing text; a Copper note becoming Gold |
| Owner-backed saved draft | Use existing account identity, lifecycle and isolation | Parallel persistence or automatic monitoring activation |
| Error/recovery | Keep navigation and selected context; retry the affected source when allowed | Global reload loop, duplicate side effects or bypassing a refused action |

## Local source checks recorded in this packet

The executable check is `node check_source.mjs`. It runs no network requests and uses a deliberately limited local DOM stub. It checks:

1. All 29 page/view combinations generate a heading and one analysis region without undefined/non-finite output.
2. Forty-eight combinations of page and primary/loading/empty/error/partial/conflict state retain navigation.
3. FX inverse arithmetic and reciprocal quote-series behavior.
4. Five-decimal tick precision for small FX quotes.
5. Delayed CHF cross cells have no current result action or value-derived color; the delayed selected pair is withheld.
6. A missing Crypto derivatives source withholds the aggregate plot.
7. Bitcoin replay changes its allocation and driver states together.
8. A valid zero model target displays zero and the corresponding cash allocation.
9. Selected performance window changes the narrative and relevant ledger context, including a period in which the model leads.
10. A selected decision opens its own date, before/after target and record identity.
11. Reserve events, capacity availability and coverage denominator are country-specific.
12. The +50 bp sample bond shock computes −$284.75 and keeps observed and scenario baselines separate.
13. URL re-reading preserves comparison, scenario and evidence context.
14. Research drafts survive a context change and retain units/source identity in the local review store.
15. Narrow chart generation uses a 340-unit geometry, rather than scaling an 820-unit plot.
16. Untrusted/malformed view URLs fall back to valid asset/view identities without injecting markup or breaking evidence rendering.

These checks intentionally do not claim browser layout, real focus, touch, downloads, clipboard, actual navigation history, cookie/session behavior, live-source correctness, protected CI or production acceptance.

## Release and acceptance receipts

For each implemented page, preserve exact code head, source/producer build, registry change, affected tests, required CI, actual reviews/protections, deploy identifier and authenticated production journey evidence. Distinguish submitted, queued, started, merged, deployed and accepted.

Completion requires the original page’s useful capabilities, shared-shell continuity, truthful source semantics, successful real consumer workflow and durable evidence. This packet is a substantial design input to that process; it is not its completion receipt.
